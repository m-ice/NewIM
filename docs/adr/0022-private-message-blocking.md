# 0022 私聊与拉黑

Task: NIM-SEC-002

私聊创建、拉黑与发送使用现有 PostgreSQL 和已验收的 Bearer 会话。客户端只提交对端账号，发起方由会话确定。登记会话类型和固定对端后，发送事务可以区分私聊和两人群聊。

## 启用和迁移

迁移 007 在会话表增加可空类型和私聊对端字段。私聊的两个对端为经过规范排序的不同有效用户，数据库保证同一对账号只有一个登记的私聊。群聊无固定对端。部署工具使用已核验的数据标记存量会话，并核对私聊成员与固定对端一致。历史数据、会话 ID 和既有迁移文件继续有效。

默认按原有规则提供发送服务。配置 `NEWIM_PRIVATE_MESSAGE_POLICY=1` 启用本策略和三个新增入口，需要同时启用既有 loopback 消息入口。启用前校验全部存量会话的类型和私聊成员。启用后遇到未分类或失配会话时，保持已有回执可重放，新发送返回临时不可用。修复关系数据后可继续发送。

## 并发与可见性

创建私聊、变更拉黑和向私聊发新消息均在数据库事务中使用同一对账号的无向锁键。关系方向由 `im_blocks` 的发起方和目标字段表达。申请锁后查询关系，保证已成功提交的拉黑可约束之后的新发送与会话创建。申请锁前验证当前发送者的会话成员身份。私聊申请锁后重新读取已提交回执，保证并发重试使用稳定的幂等结果。

新建私聊和两条成员记录一起提交。已登记的私聊返回既有 ID。对端已拉黑发起人时拒绝新建。拉黑和解除均幂等，消息历史保留。群聊发送使用现有成员权限。拒绝新发送时不分配序号、不插入消息和 outbox。

复用已有 HTTP、消息和存储错误映射。`BLOCKED_BY_RECIPIENT` 为永久拒绝，在 HTTP 返回 403。指标只增加固定错误标签。
