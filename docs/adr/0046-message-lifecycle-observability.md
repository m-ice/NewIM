# 消息追踪与端到端运行指标

## 发送关联

TLS 网关为每次发送尝试沿用服务端生成的 128 位追踪标识。当前会话完成授权，且存储已经
确认提交与回执编码后，TLS 网关通过 `X-NewIM-Trace-Id` 返回该标识。格式为 32 位小写
十六进制字符。服务端观测器使用同一标识。标识生成失败时仍可返回持久回执。

SDK 宿主在同一已验证响应中取得追踪标识和回执，并按当前连接票据及原发送意图核对
`clientMsgId`、`serverMsgId`。幂等重试保持同一逻辑发送身份，各次尝试可分别追踪。
响应元数据仅返回给当前已验证的发送者。现有回环发送和消息帧继续按原规格运行。
旧客户端可按原方式解析回执。读取到元数据不能改变发送结果、排序或本地授权。

生产日志继续使用固定阶段、错误码、耗时与计数。追踪与原始业务标识都从指标标签和
生产日志中剔除。授权诊断通过持久回执与受控数据库读取关联发送、队列及投递记录。

## 运行观测

复用已有的发送生命周期、Webhook 和持久积压指标。补充网关订阅、实时传输、目录及消息补拉，
以及 SDK 当前连接、发件队列、缺口与持久接收。观测来自实际连接、确认写入或已提交的存储
结果。复用离线推送的固定结果计数。指标按稳定组件、动作和结果聚合，写入计数或观察器失败
不阻断消息路径。服务端传输写入与 SDK 存储提交分别测量。

运维查询覆盖发送成功率和持久确认耗时、实时连接与缺口恢复、离线推送及队列积压。
测试连接真实 TLS、SDK 和存储上报路径，校验观测时点、原回执字节和脱敏。
