# SDK 消息缺口与补拉

## 决定

客户端用现有 TLS `POST /api/v1/sync/messages` 与 WSS 消息帧恢复顺序。协议适配器负责
线上编码、页上界、消息序号连续校验和无损发送意图核对。SDK 核心使用类型化消息和位点。
位点按会话保存，等价入站消息复用现有消息行，ACK 照常确认原待发记录。

SQLite 004 在已发布会话下保存连续位点、授权下界、观察到的最高序号和至多一个补拉任务。
SDK 以实际缺口安排补拉，持久化请求代次和页起点，再由宿主发起 TLS 请求。每页和位点
在一个事务提交。提交时重读当前目标，等待期间收到的实时消息可以提高目标。
只有活动任务匹配的响应才能写入消息和推进补拉状态。

补拉读取从消息位点与授权下界的较大值继续。目录切换时只使用已发布数据，可见性移除
使活动补拉失效。账号和存储世代校验与现有存储端口一致，重启时根据持久状态继续。

同位点连续失败最多八次，实际推进会重置该计数。任一任务总时限为 24 小时，沿用出站
指数退避的上下界。超出本地整页容量时按原位点缩小页，最低一条。故障恢复重新读取
已提交位点，已过期的同一次尝试最多记一次。

## 兼容

旧本地动作和序列化字节保持兼容。迁移保留原消息、待发、回执和会话目录。
裁剪后的本地消息继续保留身份；补拉和实时收敛使用原索引。
