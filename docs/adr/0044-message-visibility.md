# 权威未读和消息可见性事件

## 决定

会话引导和增量发布同一修订的 `lastReadSeq`、`unreadCount` 与消息可见性修订。
服务端以成员历史下界、个人清空位点及权威已读水位确定起点，按当前可见的接收消息计数。
自己的消息和生命周期事件不计入。SDK 提交目录检查点后使用服务端快照校正乐观未读。
发送、已读及可见性变更通过已有会话锁和投影事务协调。常规发送沿用有界投影写入，
历史重算使用会话序列、发送者和受影响消息的索引，并通过已填充数据验证查询计划。

消息可见性的变更采用追加事件。事件绑定原会话、原消息、操作身份、幂等请求与可见受众。
作者撤回要求当前可见的自发消息。管理移除要求当前群拥有者或管理员权限。个人删除只对
发起账号生效，其他设备按该账号同步。会话清空推进原有历史下界。事件提交、受众修订和
会话投影在同一 PostgreSQL 事务生效。重试先在事务中核对当前授权和既有请求意图。

原消息序列保留以支持旧设备按序拉取。撤回或隐藏后的历史页、WSS 回放和后续投递使用
对应受众的占位，保留原序号和消息标识，隐藏正文并携带 `countAsUnread: false`。
服务端读取和回放在组帧前应用可见性，内部保存的原始记录继续用于持久幂等。
客户端发送端点只接受已有的用户可发类型。服务端用独立的动作端点处理
`recall`、`deleteForMe` 和 `adminRemove`，会话清空继续经过现有端点。

会话可见性修订有独立位点。SDK 从同一 TLS 同步模块分页取得当前受众的事件，
因此在消息尾部没有推进时也能补到撤回。新会话目录目标包含可见性位点。SDK 将正文隐藏、
事件和位点一同提交到本地存储，按当前连接票据发布，拒绝旧授权回调。回放或迟到的旧消息
不能覆盖已提交的可见性状态。

## 兼容

沿用 v1 的规范十进制字符串和既有消息标识。目录新增字段可选。历史中正常可见的消息
继续按原编码产生。追加 PostgreSQL 与 SQLite 迁移，旧消息、已读、目录修订和待发送
记录可继续读取。旧库升级后的初次投影按照现有引导和回填机制发布完整状态。
