# 消息系统性能基线

在干净的产品提交上运行 `make performance-baseline`。入口复用
[PostgreSQL 测试环境](../../infra/db/README.md)，用锁定镜像创建独立容器和数据库卷。
服务端、TLS 网关和测试客户端在同一容器内运行，使用回环地址和 PostgreSQL Unix socket。
Docker 容器禁用外部网络，配额为 2 CPU、512 MiB 内存、128 个进程。

## 固定工作量

| 项目 | 测量窗口 |
| --- | --- |
| 会话登录 | 16 个已预配账号通过可信回环接口各准入一台设备，预配在窗口之外。 |
| WSS 建连 | 16 台设备按每批 4 台建连，记录从发起请求到各自收到第一条消息的时间。读取网关指标确认 16 条订阅均活跃。 |
| 消息发送及持久写入 | 单写者在小群按顺序提交 48 条文本。每条文本 64 字节。时间包含请求、提交和持久回执。以 PostgreSQL 的实际消息和 outbox 行数核对提交，分别除以同一发送窗口得到写入速率。 |
| 消息补拉 | 4 台设备分别从头读取同一批消息，每页最多 8 项。校验每页顺序、游标和消息身份，按实际页数和返回消息数分别计算速率。 |
| 网关更换及重连 | 终止测试网关并启动新进程，单独记录进程替换至运维监听可读的耗时。离线期间向新实例提交一条消息，16 台设备按每批 4 台从已读位点续读并确认订阅恢复。 |

操作速率使用完成数除以该阶段的单调时钟窗口。每个阶段记录样本数、原始纳秒值与
P50、P95、P99。分位数按最近秩计算，小样本的 P99 可能等于最大值。
发送窗口的写入速率含应用端开销。预写种子、进程替换后的额外消息，以及 SQL 核对时间
单独处理。

## 复跑和核对

每次运行使用唯一的 `build/sync-http/performance-baseline-*` 子目录，并生成
`performance-report.json`、原始测试日志、环境记录和命令清单。报告记录精确提交、源码树、
可执行文件摘要、Docker 配额与镜像、宿主硬件、运行架构、Go、PostgreSQL 和实际服务依赖版本。
认证失败、超时、样本缺失、计数不符或数据库耐久配置偏差会导致运行失败。

复跑时使用相同的镜像、工作量、宿主配置和资源配额。回环链路、固定的小群与载荷、单写者、
缓存状态和 Docker 配额都会影响读数。这些读数适用于比较同一配置下的构建变更。
