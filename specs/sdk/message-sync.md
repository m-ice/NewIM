# SDK 消息补拉

SDK 从已发布会话目录接收 WSS 消息。每会话保存最后连续实收序号、服务端历史下界、
已观察的最高序号以及一条持久缺口任务。来自旧 ACK 流程的已保存序号也能触发补拉。
实时、补拉和 ACK 共用原 SQLite 消息身份与索引。

通过 `MessageSyncSnapshot` 读取位点。宿主提交调度动作取得持久请求代次，再用对应
`InFlightPage` 向 `POST /api/v1/sync/messages` 发起鉴权 TLS 请求。请求序号取本地实收
位点与已知授权下界的较大值。响应必须按序返回同一会话消息。页的续位点为最后实收
序号，空页用于更新授权下界。完整页、位点和任务一起提交。

提交页时按当前授权下界过滤旧帧，并重新检查实时路径在等待期间看到的最高序号。
接收相同消息可复用既有记录。已裁剪的正文保持裁剪状态。自发消息与待发记录意图
等价时保留原持久编码。待发关联的正文保留到原 ACK 流程确认完成。

同一无进展位点至多八次连续失败，推进后重置计数。作业总时限为 24 小时。
本地页容量不足时原位缩页，最低一条。登录恢复后由宿主显式恢复。进程中断后的过期
尝试只记一次。旧代次、目录移除和替换后缺席会使活动请求失效。

原有消息记录、发件队列、获取回执、会话目录和老版本本地请求编码继续沿用。
SQLite 004 增加补拉事务的状态。命令 `make message-sdk-sync-check`、
`message-sdk-sync-convergence`、`message-sdk-sync-retries` 和
`message-sdk-sync-recovery` 覆盖实际 TLS/WSS、原生存储和进程恢复。
