# SDK 会话同步

宿主统一把服务器页解码为 SDK 的类型化输入，通过现有 Store 提交。引导、增量续页和检查点用原始服务端游标。
调用方为每次请求记录账号、实例、设备世代、同步轮次和输入位置。读取当前 Store 快照后计算更新，提交整页时由同一事务核对位置与存储版本。

每个会话只保留当前最高修订及有效的可选字段。重复修订按已知字段核对，较低修订忽略。
移除修订保留身份和顺序，个人清空下界用于过滤缓存或晚到的历史帧。
已知个人下界在目录移除及更换引导轮次后继续保存。会话恢复时沿用已知下界，草稿和通知偏好以恢复修订提供的字段为准。
普通本地消息分页在同一读事务使用已发布个人下界与调用方位点中的较大值。缓存行继续用于内部查找和发送确认。
已发布目录同事务接管下界后，SQLite 回收该会话的重复归档记录。
当服务端返回 `409 SYNC_CURSOR_EXPIRED`，SDK 开启新的引导轮次。终页同时发布新目录与检查点。
暂存的部分结果和前一轮迟到响应不能改变已发布目录。

SQLite 迁移 003 保存同步位置、已发布目录和暂存目录。两份目录分别受 1000 条上限保护。
整页失败、超限或进程中止时，已发布目录与游标保留可继续读取的版本。原有存储摘要、未读值、消息、待发队列及旧操作编码保持兼容。

运行 `make conversation-account-sdk-check` 通过真实 TLS 请求、PostgreSQL 和本机 SQLite 验证引导、增量、过期重建和重开续页。
