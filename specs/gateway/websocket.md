# 实时消息网关

连接使用直接 TLS 上的 `GET /api/v1/gateway`。握手需要单个 `Authorization: Bearer <token>` 头、`Sec-WebSocket-Protocol: newim.v1` 以及 RFC 6455 标准升级头。请求路径精确匹配，握手拒绝请求体、查询串及 Origin 头。客户端每次连接使用新 WebSocket 随机值。

握手失败使用 HTTP 状态码。

| 状态 | 含义 |
| --- | --- |
| 400 | 握手格式有误 |
| 401 | 缺少有效会话令牌 |
| 404 | 路径不存在 |
| 405 | 方法不受支持 |
| 409 | 已经使用过该令牌与握手随机值的组合 |
| 429 | 地址或设备超出本进程每分钟握手次数 |
| 503 | 容量暂满、服务正在排空或暂不可用 |

升级后客户端发送一条 UTF-8 JSON 文本消息。

```json
{"conversationId":"conv_123","afterSeq":"0"}
```

两个字段均必需。会话标识沿用消息协议标识格式。序号采用无前导零的十进制字符串，取值范围为 0 至 9223372036854775807。首次读取使用 `"0"`，后续重连使用客户端已持久化的游标。投递使用 [现有服务端消息帧](../protocol/send-ack.md) 的 `message` 分支。客户端须处理 WebSocket Ping 和 Close 帧。首次合法订阅和成功的心跳更新设备最近活跃时间。

服务器按成员授权范围读取。对 [小群](../group/membership.md)，游标早于授权起点时，从起点的下一条开始投递。离开后，投递截止到该成员记录中的最后授权序号，客户端可根据群变更关闭实时订阅。客户端可通过群成员状态取得历史起点和离开时的上限。

| 关闭状态 | 原因 | 客户端处理 |
| --- | --- | --- |
| 1001 | `server_draining` | 退避后携带游标重连 |
| 1008 | `session_revoked` / `device_limit` | 重新登录 |
| 1008 | `conversation_forbidden` | 停止订阅 |
| 1008 | `invalid_subscription` / `subscription_timeout` | 检查首帧内容及发送时机 |
| 1011 | `temporarily_unavailable` | 退避后携带游标重连 |

接收的订阅消息上限为 1024 字节，超过上限可收到 1009。慢连接、心跳超时或网络中断可能直接关闭传输。客户端仍从本地持久化游标恢复。浏览器接入的凭证交换由平台适配定义。
